# База данных Fasterbook: статистика чтения

Здесь лежат SQL-файлы для Supabase. Сайт сам ничего в базе не создаёт и не меняет:
SQL выполняете вы, вручную, в Supabase SQL Editor.

## Что внутри

| Файл | Что делает |
|---|---|
| `checks/00_check_existing.sql` | Только показывает, какие таблицы уже есть. **Запускать первым.** |
| `migrations/20261031120000_reading_stats.sql` | Создаёт таблицы и функции статистики. Только добавляет, ничего не удаляет и не меняет. |
| `rollbacks/20261031120000_reading_stats_down.sql` | Откат: убирает только то, что создала миграция (вместе с накопленной статистикой). |

## Как применить

1. Откройте Supabase Dashboard → ваш проект → **SQL Editor** → **New query**.
2. Вставьте содержимое `checks/00_check_existing.sql` и нажмите **Run**.
   Если в списке таблиц есть `reading_days`, `reading_finished_books` или `reading_state`,
   остановитесь и покажите результат Claude. Если их нет, идите дальше.
3. Откройте новый запрос, вставьте содержимое файла из `migrations/` целиком и нажмите **Run**.
   Должно появиться `Success. No rows returned`.
4. Проверьте: **Table Editor** покажет три новые таблицы, у каждой метка **RLS enabled**.

Миграцию можно запустить повторно, ничего не сломается.

## Что создаётся

Таблицы:

- `reading_days`: одна строка = один день чтения пользователя (дата, секунды, слова). Из неё считаются серия, рекорд и календарь.
- `reading_finished_books`: какие книги пользователь дочитал до конца (одна книга считается один раз).
- `reading_state`: служебная, нужна для защиты от накрутки времени. Из браузера не видна.

Функции (браузер вызывает только их, напрямую в таблицы писать нельзя):

- `record_reading`: засчитать прочитанные секунды и слова.
- `mark_book_finished`: отметить книгу завершённой.
- `get_reading_stats`: отдать всю статистику сразу.

## Как защищены данные

- На всех таблицах включена **RLS**: пользователь видит только строки со своим `user_id`.
- Записывать из браузера в таблицы нельзя совсем, только через функции. Они сами берут id пользователя из проверенной сессии, а не от браузера.
- Сервер не засчитывает больше времени, чем реально прошло, поэтому частыми запросами время не накрутить.
- Секретные ключи Supabase на сайте не используются.

## Правила подсчёта (можно поменять в SQL)

- День попадает в серию, если за него прочитано **не меньше 60 секунд** (`c_min_seconds` в `get_reading_stats`).
- Серия идёт, пока вы читали сегодня или вчера. Пропущенный календарный день обрывает её.
- Границы суток определяются по часовому поясу вашего устройства.

## Книги в аккаунте (`migrations/20261101120000_books.sql`)

Без этой миграции вошедший пользователь увидит в «Моих книгах» сообщение «Хранение книг в аккаунте ещё не настроено». Гостей это не касается: у них книги, как раньше, в браузере.

Как применить: так же, как статистику. Сначала `checks/00_check_existing.sql` (пункт 3 должен вернуть пустые результаты), затем **весь текст** файла миграции в SQL Editor → **Run**.

Что создаётся:

- таблица `books`: название, автор, число слов, позиция; RLS: каждый видит и меняет только свои строки;
- закрытое хранилище файлов `book-texts` (Storage): тексты книг, путь `id пользователя/id книги.txt`; в чужую папку не пускают правила доступа.

Проверка: **Table Editor** — таблица `books` с меткой **RLS enabled**; **Storage** — хранилище `book-texts` с пометкой Private.

Книги, загруженные раньше без аккаунта, остаются в браузере. После входа в «Моих книгах» появится кнопка «Перенести в аккаунт».

Откат: `rollbacks/20261101120000_books_down.sql` (перед ним вручную очистить хранилище `book-texts`).

## Избранное (`migrations/20261102120000_favorites.sql`)

Запускать **после** миграции книг. Пока она не выполнена, всё остальное работает: просто сердечко и цитаты покажут сообщение «Избранное ещё не настроено».

Как применить: `checks/00_check_existing.sql` (пункт 4 должен вернуть пустой результат), затем **весь текст** файла миграции в SQL Editor → **Run**.

Что создаётся:

- колонка `books.is_favorite` — книга в «Любимых»; у всех уже загруженных книг будет `false`;
- таблица `quotes` — сохранённые цитаты; RLS: каждый видит и удаляет только свои, добавить цитату можно только к своей книге. Если книгу удалить, цитата остаётся (с названием книги).

Проверка: **Table Editor** — таблица `quotes` с меткой **RLS enabled**, у таблицы `books` появилась колонка `is_favorite`.

Откат: `rollbacks/20261102120000_favorites_down.sql`.

## Профили и друзья (`migrations/20261103120000_friends.sql`)

Запускать **после** миграции статистики (серия дней друзей берётся из `reading_days`). Пока миграция не выполнена, раздел «Друзья» покажет сообщение «Друзья ещё не настроены», остальной сайт работает как раньше.

Как применить: `checks/00_check_existing.sql` (пункт 5: `profiles` и `friendships` быть не должно, `reading_days` — должна), затем **весь текст** файла миграции в SQL Editor → **Run**.

Что создаётся:

- таблица `profiles`: никнейм, короткий числовой ID (с 100001, его выдаёт база), настройка «показывать активность», «что читаю». Каждый видит только свой профиль;
- таблица `friendships`: заявки и друзья. Из браузера её не видно и не изменить — только через функции;
- функции `find_profile`, `send_friend_request`, `respond_friend_request`, `remove_friend`, `get_friends`. Друзья видят только никнейм, серию дней и книгу за последние 14 дней (если человек не выключил это). Почту не видит никто.

Никнейм вводится при регистрации и хранится в данных аккаунта; профиль создаётся при первом открытии «Друзей». Кто зарегистрировался раньше, придумает никнейм там же.

Проверка: **Table Editor** — таблицы `profiles` и `friendships` с меткой **RLS enabled**.

Откат: `rollbacks/20261103120000_friends_down.sql`.

## Друзья онлайн (`migrations/20261104120000_friends_online.sql`)

Запускать **после** миграции друзей. Добавляет в `profiles` колонку `last_active_at`, функцию `mark_active()` и обновляет `get_friends` (новое поле `online`). Ничего не удаляет.

Пока сайт открыт и вкладка видна, браузер раз в 2 минуты вызывает `mark_active()`, время ставит сама база. Друг «в сети», если отметка была за последние 5 минут и он не скрыл активность. До применения миграции сайт работает, просто никто не показывается в сети.

Как применить: `checks/00_check_existing.sql` (пункт 6 — должна вернуться строка `get_friends`), затем весь текст файла миграции → **Run**.

Откат: `rollbacks/20261104120000_friends_online_down.sql`.

## Известные ограничения

- Статистику «завершённых книг» ведёт идентификатор книги из браузера. Пока книги хранятся только в браузере, одна и та же книга, загруженная на двух устройствах, считается дважды.
- Если закрыть вкладку внезапно, могут потеряться последние до 10 секунд чтения.
- Пользователь может исказить только собственную статистику, чужую нет. Друзья видят серию дней, поэтому теоретически её можно «накрутить», читая с открытой вкладкой. Если появятся рейтинги и соревнования, защиту придётся усилить.
- Серия друга считается по вашей сегодняшней дате. Если друг живёт в другом часовом поясе, на границе суток серия может отличаться на день.
- По ID можно узнать только никнейм человека. ID выдаются по порядку, поэтому перебором можно увидеть никнеймы, но не почту и не статистику.
